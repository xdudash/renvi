# Первая сборка TestFlight: что нужно сделать

Ревизия для сборки — последний коммит `main` после слияния PR #70 и #71 (SHA записать в момент сборки).
Развёртывание Supabase выполняется отдельно по `docs/SUPABASE_READINESS.md` (PR #68) — здесь только то, что нужно для сборки и первого теста.

## 1. Развёртывание Supabase (отдельный этап, не в этом PR)
Миграции 0036–0045 одним заходом (`db push --dry-run`, ожидается ровно этот список), затем функции из той же ревизии и вебхуки.
Минимум для первого теста без платежей и почты:
- миграции 0036–0045; функции `push`, `plan-check`, `delete-account`, `export-data`, `playbook-sync`, `plus-sync`, `boost-sync`, `revenuecat-webhook`, `weekly-digest`, `video-call`;
- секреты `PUSH_WEBHOOK_SECRET` и `DIGEST_CRON_SECRET`; Database Webhooks в `push` для `messages`, `plan_messages`, `matches`, `dates`, `video_calls`; расписание `plan-check` (каждые 15 минут) — если нужно проверить пуши и «Всё ок?»;
- до платежей не нужны: `REVENUECAT_SECRET_KEY`, `REVENUECAT_WEBHOOK_SECRET`, webhook в RevenueCat. Без ключа `plus-sync`/`boost-sync` отвечают 503, приложение показывает «покупки недоступны».
- не менять Site URL и подтверждение почты. Письма идут через уже настроенный SMTP Hostinger; доставка не проверялась.

## 2. Данные в приложении (админка → «Настройки»)
Без этого production-сборка не пройдёт строгую проверку (`check-release.mjs --strict`):

## 4. Что приложение делает без ключей покупок
Экраны Plus, буста и Playbook показывают «покупки пока недоступны»; кнопка «Восстановить покупки» на экране Plus скрыта; синхронизация подписки не запускается, ничего не падает.

## 5. Что проверить на iPhone (в вебе проверить нельзя)
1. Регистрация → письмо → подтверждение по ссылке → возврат в приложение; восстановление пароля.
2. Онбординг: клавиатура и safe area на всех шагах, разрешения геолокации, фото/камеры; загрузка фото и видео, селфи-проверка.
3. «Люди» → искра (удержание) → взаимность → чат; фото в чате по согласию; жалоба и блокировка.
4. Планы: создать → заявка с другого аккаунта → принятие → групповой чат → опрос → «Как прошло» → «В компанию».
5. Push: разрешение, токен, доставка сообщения личного чата и чата плана, переход по нажатию (холодный и тёплый старт), отсутствие имён и текста на экране блокировки.
6. Ссылки: приглашение (`renvi://` и web), ссылка на план, подтверждение почты, сброс пароля.
7. Выход, удаление аккаунта (сообщение о подписке), экспорт данных, смена языка.
8. Офлайн: режим самолёта на списках, в чате (сообщение сохраняется и уходит позже), повтор после ошибки.
9. Покупки: убедиться, что везде «недоступно», без падений.
