# Аудит веб-админки (`/admin`)

Проверено: все экраны `src/app/admin/*`, `src/components/AdminUI.tsx`, `src/components/admin/*`, `src/lib/adminApi.ts`, строки `adm.*`,
SQL из миграций 0003, 0009, 0023, 0025, 0026, 0027, 0028, 0029, 0033 и тесты `supabase/tests/admin.sql`, `analytics.sql`, `demo_access.sql`.
Для каждого RPC прочитано тело функции: имена аргументов, проверка `admin_guard()`, причина, запись в `admin_actions`, защита последнего админа.
Вёрстка оценена по коду для ширин 1280 px (боковое меню) и 393 px (телефон). Столбец «Вердикт»: **ок** — работает от начала до конца,
**дефект** — исправлено в этой ветке, **убрано** — функция удалена как лишняя.

Что подтверждено без замечаний: каждый `admin_*` RPC — `security definer`, фиксированный `search_path`, `admin_guard()` первым, `EXECUTE` только у
`authenticated` (тест каталога в `admin.sql`); каждая запись в базе пишет строку в `admin_actions`; причина (≥ 3 символа) обязательна на сервере для
санкций, снятия, решений по жалобам и апелляциям, отказа в селфи, удаления фото, добавления/удаления админа и исправления даты рождения/гендера;
последнего админа нельзя удалить ни через RPC, ни прямым `delete` (триггер `admins_keep_one`); админа нельзя заблокировать или приостановить;
`app_config` меняется только через `admin_config_set` (проверка + журнал).

## Известные ограничения (не менялись)

- «Удалить фото» убирает запись, файл в хранилище лежит до очистки.
- Любой админ может забрать себе жалобу, назначенную коллеге (через «Взять себе» после «Вернуть в очередь» или из фильтра «Все»); решение по ней всё равно пишется с именем решившего.
- Боковое меню переключает разделы через `router.replace`, кнопка «Назад» браузера возвращает из админки, а не к прошлому разделу; карточки пользователей открываются через `push` и возвращают назад.
- Многоключевое сохранение «Документы и поддержка» выполняет два вызова; оба проверяются тем же правилом на клиенте, расхождения сервера практически невозможны.

## Тесты

- `supabase/tests/admin_ui.sql` — проверка `discover_recycle`, добавление админа (подтверждённая и неподтверждённая почта), предупреждение видно пользователю и ничего не ограничивает, блокировка и разблокировка, очередь «open», журнал ошибок только для админов, каждая группа фильтра журнала.
- `e2e/admin-ui.e2e.mjs` — вход под админом, обход каждого экрана на 1280 px и 393 px, нажатие каждой кнопки и проверка записи в базе и журнале.
