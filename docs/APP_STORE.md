# RENVI в App Store: комплект для отправки (iOS)

Этот файл — всё, что нужно для первой отправки RENVI в App Store: что уже настроено в коде, что вписать в App Store Connect и что может сделать **только основатель**. Приложение распространяется только для iPhone, встроенных покупок нет.

Проверка перед сборкой:

```bash
node scripts/check-release.mjs            # статическая проверка (то же самое запускает CI, шаг «App Store release gate»)
npm run release:check                     # = check-release.mjs --strict: плюс боевой Supabase, ссылки на документы, e-mail поддержки
```

`--strict` берёт `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_ANON_KEY` из окружения или из `.env` и не пройдёт, пока в боевом `app_config` пусты ссылки на документы или e-mail поддержки, а также если какая-то из страниц не открывается.

| Заставка | `splash` в `app.json` | см. «Не проверено» ниже |
| Фоновые режимы | — | нет: ни фоновой геолокации, ни фонового аудио, ни фоновых push (`enableBackgroundRemoteNotifications: false`, `supportsBackgroundPlayback/PictureInPicture: false`) |
| Отслеживание (ATT) | — | нет. `NSPrivacyTracking: false`, запроса App Tracking Transparency нет и не нужно |

### Разрешения (тексты, которые видит пользователь)

Все тексты — по-русски (основной язык приложения). Переводы интерфейса (SK/CS/EN/UA) основатель даёт сам, машинного перевода нет, поэтому английских текстов разрешений пока тоже нет; когда появятся переводы — добавить их через `expo.locales`.

| Ключ Info.plist | Откуда | Зачем в коде | Текст |
|---|---|---|---|
| `NSCameraUsageDescription` | плагин `expo-image-picker` | селфи-проверка (`src/lib/verification.ts`), видеозвонок перед встречей (WebView Daily.co) | «Камера нужна для селфи-проверки и для видеозвонка перед встречей, если вы на него согласитесь. Селфи не становится частью анкеты.» |
| `NSMicrophoneUsageDescription` | `expo-image-picker` | только видеозвонок перед встречей | «Микрофон нужен только для видеозвонка перед встречей, на который вы согласились. RENVI не записывает звонки.» |
| `NSPhotoLibraryUsageDescription` | `expo-image-picker` | фото/видео анкеты (`usePhotos.ts`), фото в чате | «RENVI открывает галерею, чтобы вы сами выбрали фото и короткие видео для анкеты или фото для чата. Другие файлы приложение не видит.» |
| `NSLocationWhenInUseUsageDescription` | `expo-location` | примерное расстояние (`src/lib/location.ts`, точность `Low`) | «Местоположение нужно только для примерного расстояния. Координаты округляются примерно до 1 км и никому не показываются.» |
| `NSLocationAlwaysAndWhenInUseUsageDescription`, `NSLocationAlwaysUsageDescription` | `expo-location` | **не запрашиваются**: код вызывает только `requestForegroundPermissionsAsync`. Ключи оставлены с честным текстом, потому что библиотека содержит код фоновой геолокации и проверка загрузки Apple (ITMS-90683) может потребовать эти строки | «RENVI использует местоположение только пока приложение открыто — для примерного расстояния. Фоновый доступ не запрашивается.» |
| Push-уведомления | `expo-notifications` | сообщения, совпадения, свидания | текст не нужен, iOS показывает системный вопрос; есть отдельный экран-объяснение `/push-prompt` |

Контакты, календарь, Bluetooth, Face ID, отслеживание — не используются и не объявлены.

**Собираемые данные** — все «связаны с пользователем», ни одни «не используются для отслеживания». Таблица в разделе 3 повторяет их для анкеты App Privacy.

## 4. Сборка, TestFlight, отправка

Команды запускаются из корня проекта; EAS CLI — `npx eas-cli@latest …`.

1. Один раз: `npx eas-cli@latest login`, `npx eas-cli@latest init` (создаст `extra.eas.projectId` в конфиге — закоммитить).
2. Переменные боевой сборки (окружение EAS `production`, его читает профиль `production`):
   ```bash
   npx eas-cli@latest env:create --environment production --name EXPO_PUBLIC_SUPABASE_URL --value https://<ref>.supabase.co --visibility plaintext
   npx eas-cli@latest env:create --environment production --name EXPO_PUBLIC_SUPABASE_ANON_KEY --value <anon key> --visibility plaintext
   npx eas-cli@latest env:create --environment production --name EXPO_PUBLIC_APP_URL --value https://<домен> --visibility plaintext
   ```
   Без первых двух приложение покажет экран «не настроено» — гарантированный отказ ревью.
   (Если собираете через GitHub — Actions → EAS Build and Update, — значения берутся из переменных репозитория и подставляются в `eas.json` автоматически, см. `docs/SETUP.md`.)
3. Проверка: `npm run release:check` (с теми же значениями в `.env`) — должно быть `release check ok`. В GitHub-сборке с профилем `production` этот же строгий шаг запускается автоматически и останавливает сборку, пока документы/e-mail поддержки не заполнены.
4. Сборка: `npx eas-cli@latest build --platform ios --profile production`. При первой сборке EAS предложит войти в Apple ID и сам создаст сертификат дистрибуции, профиль и ключ APNs (ответьте «да» на вопрос про push-ключ).
5. Отправка в App Store Connect: `npx eas-cli@latest submit --platform ios --profile production --latest`
   (или сразу `build … --auto-submit`). Без интерактива нужен ключ App Store Connect API: `npx eas-cli@latest credentials --platform ios` → App Store Connect: Manage your API Key.
6. Когда запись приложения создана, впишите в `eas.json` → `submit.production.ios` реальные значения (их нельзя заменить переменными окружения — EAS их не подставляет, поэтому в репозитории их пока нет):
   ```json
   "ios": { "ascAppId": "<Apple ID приложения, только цифры>", "appleTeamId": "<Team ID, 10 символов>" }
   ```
   `release:check` напоминает, пока они не заполнены.
7. **TestFlight**: сборка появится в App Store Connect → TestFlight через 5–30 минут после обработки. Внутренние тестировщики (до 100, члены команды) — сразу. Внешние — нужна бета-проверка Apple (заполнить «What to Test», контакт и ревью-аккаунт). Пройти на реальном iPhone: регистрация с подтверждением почты, анкета, селфи, разрешения (камера, галерея, геолокация, push), чат, жалоба, блокировка, удаление аккаунта, офлайн-режим.
8. **Отправка на ревью**: App Store → версия 1.0.0 → выбрать сборку → заполнить всё из раздела 3 → Add for Review → Submit.

Номер сборки EAS увеличивает сам. Для следующей версии в магазине поднимите `expo.version` (1.0.1, 1.1.0 …) — от неё зависит `runtimeVersion` (политика `appVersion`).

## 5. Демо-боты и ревью-аккаунт

- Демо-боты (`public.demo_bots`, адреса `@demo.renvi.app`) автоматически отвечают искрой реальным пользователям. Для ревьюера это выглядит как фальшивые анкеты (риск отказа по 2.1/5.6). **Не давайте ревьюеру логин демо-бота** и до отправки на ревью удалите ботов: `scripts/check-no-demo-bots.sql`, затем `scripts/remove-demo-bots.sql` (см. комментарии в файлах). Перед публичным запуском ботов быть не должно в любом случае.
- Ревью-аккаунт — обычная регистрация через приложение на ящик, к которому у вас есть доступ: подтвердить почту, пройти анкету, одобрить селфи в админке. Второй аккаунт сотрудника — в том же городе, сделать с ним совпадение и пару сообщений, чтобы ревьюер мог проверить жалобу и блокировку в чате.
- Ревьюер обычно находится в США: если подбор ограничен странами запуска, ленты «Знакомства» у него без вашей подготовки будет пустой. Укажите в анкете ревью-аккаунта город запуска, держите в нём 2–3 анкеты сотрудников и упомяните это в заметках.
- Пароль ревью-аккаунта не менять, пока идёт проверка. Удалять аккаунт ревьюер может — заведите запасной.

## 6. Только основатель (чек-лист)

1. [ ] **Apple Developer Program** (99 USD/год) на юрлицо или физлицо. Для юрлица нужен D-U-N-S. Имя продавца в App Store = имя аккаунта.
2. [ ] **App Store Connect**: принять соглашения (Agreements), для бесплатного приложения достаточно Free Apps Agreement. Заполнить налоговые/банковские данные не требуется, пока нет покупок.
3. [ ] **Подтвердить bundle ID `com.renvi.app`.** После первой загрузки сборки он навсегда привязан к записи приложения; сменить можно только создав новое приложение (и потеряв отзывы/рейтинг). Если нужен другой — поменяйте **до** первой сборки в `app.json` и в `PINNED_BUNDLE_ID` в `scripts/check-release.mjs`. Android `package` тоже `com.renvi.app`.
4. [ ] **Запись приложения** в App Store Connect (My Apps → +): платформа iOS, имя `RENVI — знакомства` (имя должно быть свободно), язык Русский, bundle ID, SKU. Затем `ascAppId` и `appleTeamId` в `eas.json` (раздел 4, шаг 6).
5. [ ] **EAS**: аккаунт Expo, `eas init`, учётные данные iOS (сертификат, профиль) и **ключ APNs** — создаются при первой `eas build`; переменные окружения `production` (раздел 4, шаг 2). Ключ App Store Connect API — для `eas submit` без интерактива.
6. [ ] **Документы опубликованы на https**: политика конфиденциальности, условия использования, правила сообщества, правила модерации и обжалования. Политика должна описывать: какие данные (раздел 3), зачем, сроки хранения, удаление аккаунта в приложении, обработчиков (Supabase — хостинг в ЕС, Daily.co — видеозвонки, Resend — письма, Apple/Expo — push), контакты. Затем вписать ссылки в админке → Настройки → «Документы и поддержка». Ссылка «Подписки и возвраты» не нужна — покупок нет.
7. [ ] **E-mail поддержки** — живой ящик, в админке → Настройки → «Документы и поддержка». Страница Support URL с этим адресом.
8. [ ] **SMTP в боевом Supabase** (Resend или свой) и шаблоны писем — по `docs/AUTH_SETUP.md`. Без него ревьюер не сможет зарегистрироваться.
9. [ ] **Боевой Supabase**: все миграции применены, Edge Functions развёрнуты (`delete-account`, `export-data`, `push`, `video-call` …), секреты заданы, Redirect URLs (`renvi://**`), подтверждение почты включено, rate limits включены — по `docs/SETUP.md`. Проверить удаление аккаунта на боевом проекте вручную.
10. [ ] **Видеозвонок**: либо задан `DAILY_API_KEY` и звонок проверен на iPhone, либо ключ не задан (кнопка звонка скрыта) — не оставлять полусломанным.
11. [ ] **Модерация**: кто и как быстро разбирает жалобы (Apple ждёт реакции на жалобы в течение 24 часов, отражено в заметках для ревьюера).
12. [ ] **Ревью-аккаунт + второй аккаунт** сотрудника (раздел 5), данные — в App Review Information.
13. [ ] **Демо-боты удалены** (раздел 5) — до отправки на ревью, обязательно до публичного запуска.
14. [ ] `npm run release:check` проходит → сборка → TestFlight-проверка на реальном iPhone → отправка.
15. [ ] Ответить на анкету возрастного рейтинга и App Privacy (раздел 3), выставить 18+.
16. [ ] Страны продаж: только рынки, где документы проверены юристом (ЕС: DSA — контакт для жалоб на незаконный контент, GDPR). Для ЕС Apple требует указать статус **трейдера** (DSA) — адрес и телефон будут показаны в карточке.

## 7. Не проверено / ограничения

- Нативная сборка (`eas build`, `expo prebuild`) в этой среде **не запускалась** (npm-реестр недоступен, `node_modules` неполные). Конфигурация проверена по документации Expo SDK 58 и `scripts/check-release.mjs`.
- **Заставка**: в справочнике app.json SDK 58 верхнеуровневое поле `splash` не описано, рекомендован плагин `expo-splash-screen`, а пакета нет в зависимостях. Перед первой сборкой: `npx expo install expo-splash-screen` и перенести настройки в плагин (`["expo-splash-screen", { "image": "./assets/splash-icon.png", "imageWidth": 200, "resizeMode": "contain", "backgroundColor": "#F7F5F2" }]`), убрать `splash`. Проверить `npx expo-doctor`.
